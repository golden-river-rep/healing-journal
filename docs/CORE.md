# Healing Journal 通用核心规则

本项目把用户主动授权的聊天、日记整理为可审核的 Obsidian 笔记及创作草稿。只读取指定文件或指定收件目录的新材料，不读取完整历史，不自动连接 ChatGPT，不上传私人数据到 Git。

## 执行入口
“写到日志中”：整理当前授权材料为日记草稿。“整理今天的，生成全套”：日记、小红书、公众号、小说素材四类草稿。“确认发布”：只发布用户明确批准的具体版本，不默认批准所有历史草稿。

先读取 README.md、config/settings.json（不存在则参考示例配置），然后读取 .agents/skills/healing-journal/SKILL.md。全套创作再依次读取同级 healing-xiaohongshu、healing-wechat-essay、healing-fiction-seeds 的 SKILL.md。目录名不代表仅限 Codex；这些文件是可被其他助手读取的 Markdown 工作规范。

## 证据与风格
保留用户原话、感受、思考、AI 重要建议以及有证据的认识变化。区分原话、非逐字回顾、历史 AI 回答、新增解释和心理学假设。不诊断、不替用户宣布成长。来源日期不明或冲突时列为待确认，整理日期不代替事件日期。小说新增情节标记虚构，不回写事实记录。

私人参考及偏好放 private/style/，创作输出放 creative-drafts/，日记输出放 drafts/。未提供范文则使用通用初版，不声称模仿了用户。改稿形成的偏好先待确认。现有文件不覆盖；给新版本命名。

## 文件和发布
JSON 导入使用独立 Python CLI，Markdown 可由助手直接整理。Python 3.11+，无第三方依赖。外部 Vault 以用户配置为准，只写 Healing Journal 子目录；发布需批准摘要且拒绝覆盖。不能运行脚本时输出 Markdown 供用户保存，不声称已经写入本地。不能读取文件时请用户提供指定内容，不声称已读取。

## 定时运行
仅消费 imports/inbox 中用户主动投放的新文件；该目录的投放表示允许整理为草稿，不代表公开发布。历史归档及已有草稿不能当新材料重新加工。先看 private/processed.json 记录的文件内容 SHA256；同内容不重复处理。只有全部草稿成功保存才记录已处理；失败留待重试。没有新内容就不生成空日记，也不凭聊天记忆补齐。运行后报告新增草稿和待确认项，不自动发布、提交 Git 或推送平台。不同工具不要同时运行同一收件箱。
